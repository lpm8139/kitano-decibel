# 声の大きさ競争（きたのにほんいち）

「数秒間、声を出し続ける」競技の音量計測アプリ。その日のベスト記録を「ゴースト」にして、挑戦者と並べてレース表示する。
ビルド不要（素の HTML / CSS / JS）。Windows PC の Chrome / Edge を想定。

## 起動方法

1. `start.bat` をダブルクリック。黒いウィンドウで**環境チェック**が走り、問題なければブラウザが自動で開く。
   - サーバーのウィンドウは本番中は閉じない（閉じても計測は続けられる。もう一度 `start.bat` を実行すれば未保存分は自動で再送される）。
2. 初回はブラウザのマイク許可ダイアログで「許可」。
3. 右上に「ファイルに保存済み ✓」と「マイク: （デバイス名）」が緑で出れば準備完了。
4. `F` キーで全画面にして、PC をプロジェクターへ出力する。

> `index.html` を直接開いても動かない（画面上部に赤い案内が出る）。必ず `start.bat` から開くこと。

### 起動時の環境チェック（毎回自動）

当日の PC が普段と違っても動くように、`start.bat` が毎回以下を確認して結果を表示する（`data/env-check.log` にも残る）。

| チェック | 問題があったとき |
|---|---|
| Python 3.8 以上があるか | 無ければ **Windows 標準の PowerShell 版サーバー（`server.ps1`）で起動**。インストール不要 |
| PowerShell 版の JSON 処理が正しく動くか（自己テスト） | 失敗したら止まって案内を出す（Python を入れれば確実） |
| `data/` フォルダに書き込めるか | 読み取り専用の場所なら `%LOCALAPPDATA%\kitano-decibel\data` に切り替えて、保存先を表示 |
| ポート 8000 が空いているか | 使用中なら 8001〜8010 を順に使う（記録はファイルから戻るので問題なし） |
| ブラウザ | Chrome → Edge（Windows 標準）→ 既定のブラウザ の順で開く |

**本番前に当日の PC で一度 `start.bat` を実行し、全部 `[OK]` になることを確認しておくと安心。**

## 操作

| キー | 動作 |
|---|---|
| Space | 待機 → スタンバイ。スタンバイ中に押すと手動で即開始。結果画面では「次の人のスタンバイ」へ |
| Esc | 中断（スタンバイ・計測中）。結果画面では名前を確定して待機へ。設定パネルは閉じる |
| F | 全画面の切替（全画面中は Esc を中断に使うため、解除は F） |
| S | 設定パネルの開閉（待機中のみ） |
| Enter | 結果画面で名前を決定して待機へ |

### 競技の流れ

1. 待機中に Space → **スタンバイ**（15 秒反応がなければ待機に戻る）。
2. **設定しきい値を超えた瞬間に計測開始**（スタート合図の反応遅れで不利にならない）。
3. 設定秒数（既定 5 秒）で終了 → **結果表示**（記録は表示と同時に自動保存。名前は後から付けられる）。
4. 名前を入力して Enter（空欄でも可）→ 待機へ。

### 画面の見方

- 中央: 現在の dB（巨大表示）、残り秒数。
- 下: 2 レーンのレース。上が挑戦者、下がゴースト（本日ベストを同じ経過時間で再生）。
  - バーは `progress(t) = Σ max(0, dB − floor)` の**生の累積値**。最終スコアでは正規化しない。
  - 挑戦者がリードしている間は緑 +「リード中！」、抜かれている間は赤 +「追いかけろ！」。逆転時に大きく「逆転！」と出る。
  - 本日の記録がまだ無いときはゴーストなしの単独表示。
- 本日ベストを超えたら「NEW RECORD!」とフラッシュ演出。
- 右: 本日 TOP10。下部に CSV 出力・設定・本日の記録リセット。

### スコアの計算

- 既定: 計測区間の dB サンプル（約 20Hz）の**算術平均**。小数 1 桁。
- 設定で「エネルギー平均 Leq」（`10·log10(mean(10^(dB/10)))`）に切替可。声に強弱があるほど平均より高く出る。
- 同点は先に記録した方が上位。
- progress は、サンプル間隔の揺らぎで有利不利が出ないよう、各サンプルの寄与に「経過時間差 / 50ms」を掛けている（ちょうど 20Hz なら素の Σ と一致）。

## 本番前の機材セッティング

### DJI Mic Mini（レシーバーを USB-C で PC に接続。普通のマイクとして認識される）

- **DJI Mimo アプリで次を設定する**【要確認: メニュー名はファームウェア/アプリのバージョンで異なる】
  - 自動リミッター（セーフティトラック/リミッター系）: **OFF**
  - ノイズキャンセル: **OFF**
- **ゲインは本番前に固定し、本番中は触らない。** ゲインを変えると記録の公平性が崩れる。
- 送信機（マイク）は**スタンドで口から一定距離に固定**する（例: 口から 10〜15cm、口の正面から少しずらして吹かれを避ける）。手持ち・襟付けは距離がばらつくので不可。
- 距離・向きを全員同じにするため、床にテープで立ち位置を示すとよい。

### ブラウザ側

- マイク入力は `echoCancellation` / `noiseSuppression` / `autoGainControl` をすべて OFF で取得している（生の音量を測るため）。
- Windows のサウンド設定（録音デバイスのプロパティ）に「ノイズ抑制」「音声強調」「AGC」がある場合も OFF にする。
- 右上に赤く `CLIP!` が出たら、入力が -1 dBFS 付近で音割れしている。マイクのゲインを下げる（本番前に調整して固定）。

## 校正手順（dB を実際の騒音レベルに近づけたいとき）

画面の値は `dBFS + 校正オフセット`。既定のオフセット +100 は**仮の値**。順位付けだけなら校正は不要（全員同じ条件なので順位は変わらない）。

1. スマホの騒音計アプリを、マイクのすぐ横（同じ位置）に置く。
2. S キーで設定を開く。「現在の入力」に dB と dBFS が出る。
3. 一定の音を出し続ける（スピーカーから鳴らすピンクノイズや単音、または「あー」と一定の声）。
4. スマホの値と、設定画面の **dBFS** を同時に読む（数秒の平均的な値で）。
5. `オフセット = スマホの dB − dBFS` を設定に入力する。
   - 例: スマホ 85 dB / dBFS -18 のとき、オフセット = 103。
6. 声の大きさを数段階変えて、差が一定か確認する。

注意:
- スマホアプリは A 特性（dBA）が多く、本アプリは無加重の値なので**完全には一致しない**。おおまかな目安として扱う。
- 校正は本番前に済ませ、**記録が入った後でオフセット・スコア方式を変えない**（過去の記録と比較できなくなる）。変えた場合は「本日の記録をリセット」してやり直す。

## 設定項目（S キー。`data/settings.json` とブラウザの両方に自動保存）

| 項目 | 既定 | 意味 |
|---|---|---|
| 入力デバイス | 既定のマイク | 選択は保存される |
| 計測秒数 | 5（3〜10） | 声を出し続ける秒数 |
| 開始しきい値 | 65 dB | 超えた瞬間に計測開始（仮値。会場の環境音より十分高く、声より十分低く） |
| floor | 40 dB | これ以下は競争ポイントに加算しない |
| 校正オフセット | +100 dB | 上記の校正を参照（仮値） |
| スコア方式 | 平均 | 平均 / Leq |

## 記録の保存（PC のファイルに自動保存）

記録は **1 件ごとに自動で PC のファイルに保存**される（ブラウザ内にも控えを持つ二重保存）。保存先は設定画面（S）に表示される。通常はアプリのフォルダ内の `data/`。

```
data/
  2026-10-10.json            その日の全記録（本体）
  2026-10-10.log.jsonl       記録を1件ずつ追記するだけのログ（最終保険。破棄・リセットしても消えない）
  history/2026-10-10_*.json  上書き前の世代コピー（直近20件）
  settings.json              設定（校正オフセットなど）
  env-check.log              起動時の環境チェック結果
```

- 書き込みは「一時ファイルに書いてから置き換え」方式なので、保存の途中で PC が落ちてもファイルは壊れない。
- 保存サーバーが止まっても計測は続けられる。右上が「未保存あり・再送中」（赤）になり、サーバーが戻ると 5 秒ごとの再送で自動的に保存される。
- ブラウザやポート番号が変わっても、起動時にファイルから記録と設定を読み込むので元に戻る。
- 「この記録を破棄」「本日の記録をリセット」はランキングから外すだけで、ファイル上には「破棄済み」として残る。
- 「CSV出力」で本日の記録をランキング順に出力（`kitano-decibel_YYYY-MM-DD.csv`、Excel でそのまま開ける UTF-8 BOM 付き）。
- 日付（PC のローカル日付）ごとに別ファイル。日付が変わると新しい日の記録になる。

**イベント後は `data/` フォルダごと USB などにコピーしておく。**

### 復旧方法

| 状況 | 方法 |
|---|---|
| 間違えて破棄・リセットした | `data/<日付>.json` を開き、該当記録の `"deleted": true` を消して保存 → ブラウザを再読み込み |
| `<日付>.json` が壊れた/消えた | `history/` の一番新しいファイルを `data/<日付>.json` にコピー。それも無ければ `.log.jsonl`（1行1記録）から復元できる |
| 別の PC で続きをやりたい | アプリのフォルダごと（`data/` 込みで）コピーして `start.bat` |

## 当日のトラブル対応

| 症状 | 対処 |
|---|---|
| 右上が「マイクエラー」/ 赤字メッセージ | メッセージに従う。まず下の各項目を確認 |
| マイクが出ない・音量が動かない | S → 入力デバイスで DJI のレシーバー（DJI MIC MINI など）を選ぶ。USB を挿し直したら再度選択 |
| 「マイクの使用が許可されていません」 | アドレスバー左の鍵/設定アイコン → マイクを「許可」→ F5 で再読み込み。Windows の「設定 → プライバシー → マイク」でブラウザが許可されているかも確認 |
| 「他のアプリが使用中」 | Zoom / Teams / DJI Mimo などマイクを掴んでいるアプリを閉じる |
| 「マイク待機中（クリックで開始）」 | 画面をクリックするか何かキーを押す（ブラウザの自動再生制限） |
| 計測が始まらない | しきい値が高すぎる、またはマイクが別デバイス。S の「現在の入力」で声を出して値を確認し、しきい値を調整 |
| 声を出す前に始まってしまう | しきい値が環境音より低い。S で上げる（BGM が大きい会場では特に） |
| CLIP! が出る | マイクのゲインを下げる。ただし本番中の変更は公平性が崩れるので、変えたら全員やり直し |
| 上部に赤帯「保存サーバーにつながりません」 | `start.bat` の黒いウィンドウが閉じていないか確認。閉じていたらもう一度 `start.bat` → 未保存分は自動で再送される |
| 環境チェックで `[NG]` | 表示された案内に従う。PowerShell 版で NG なら Python 3 をインストール（https://www.python.org/downloads/ 、Add python.exe to PATH にチェック） |
| マイクが「選んだマイクが見つからない」と出る | ポートやブラウザが変わるとマイクの選択が引き継がれない。S で選び直す |
| 全画面で Esc が効かない | F で全画面を解除してから操作 |
| ページを誤って閉じた | `start.bat` から開き直せば、ファイルから記録が戻る |

## ファイル構成

```
index.html        画面
css/style.css     プロジェクター向けスタイル（rem 基準で画面サイズに比例）
js/audio.js       マイク入力（getUserMedia + AnalyserNode、約20Hz）
js/scoring.js     純関数: RMS→dBFS、平均、Leq、累積 progress、ゴースト補間
js/storage.js     日付キー、ランキング、破棄（tombstone）、設定の正規化、CSV、localStorage 読み書き
js/sync.js        保存サーバーとの同期（マージ・送信キュー・自動再送）
js/render.js      DOM 更新
js/app.js         状態遷移・キー操作・配線
tests/            node --test 用テスト（*.test.js）と保存サーバーの API テスト（test_api.py）
start.bat         起動用（環境チェック → server.py か server.ps1 を起動）
server.py         保存サーバー（Python 標準ライブラリのみ）
server.ps1        保存サーバー（Python が無い PC 用。Windows 標準の PowerShell で動く。API・保存形式は server.py と同じ）
data/             記録の保存先（起動時に自動作成。Git には入れない）
```

## テスト

Node.js 20 以上（動作確認は 22）。ブラウザ不要。

```
node --test
```

`scoring.js` `storage.js` `sync.js` が対象。保存サーバーは同じテストを両方の実装に当てる:

```
python -m unittest discover -s tests -p "test_*.py"                          # server.py
set "KITANO_SERVER=powershell" && python -m unittest discover -s tests -p "test_*.py"   # server.ps1
```

マイク・描画は実機での確認が必要（下記チェックリスト）。

### 本番前の実機チェックリスト

- [ ] DJI Mic Mini 接続で、設定の「現在の入力」が声に反応する
- [ ] 同じ声量で何度か測ってスコアのばらつきが小さい（マイク固定・ゲイン固定）
- [ ] 大声で `CLIP!` が出ない（出るならゲインを下げて再確認）
- [ ] プロジェクターに映して文字が読める（明るい会場なら環境光に注意）
- [ ] 1 人目（ゴーストなし）→ 2 人目（ゴーストあり）→ 逆転の演出を通しで確認
- [ ] CSV 出力が Excel で文字化けせず開ける
- [ ] 当日の PC で `start.bat` の環境チェックが全部 `[OK]`、右上が「ファイルに保存済み ✓」
- [ ] 1 件記録したあと `data/<日付>.json` ができている
- [ ] 黒いウィンドウを閉じる → 1 件記録（赤帯が出る）→ `start.bat` で再起動 → 自動で保存される
- [ ] リリハで入れた記録を、本番前に「本日の記録をリセット」で消す
